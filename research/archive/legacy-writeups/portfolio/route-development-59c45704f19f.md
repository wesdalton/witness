# Free route-task development and validity record

Before any route-task model inference, independent Python path enumeration and
SQL recursion agreed on all 1,024 five-node DAGs under three risk-group assignments.
Separate cases cover two paths sharing a risk group, repeated risk within one path,
direct-only graphs, infeasibility, and direct-plus-indirect paths.

The first replay mutation gate failed: all eight ordinary random graphs happened
to admit an optimal solution containing a cheapest individual path. Their renamed
copies and six boundary cases also missed the greedy-first fault. Eight of nine
authored incorrect queries were distinguished. The diagnostic is preserved in
route-mutation-gate-initial-failure.json. This was a local validity-gate failure,
not a Daybreak rejection, and no paid route requests were dispatched.

Amend the replay gate before agent outcomes exist: add one independently qualified
greedy-failure graph per fresh seed, alongside the ordinary and renamed ordinary
graphs. Qualification checks reference semantics only, never model answers.
The resulting planned replay set has 30 conditions: eight qualified traps, eight
ordinary graphs, eight renamed graphs with changed endpoints, and six boundaries.
Do not report its trap-enriched failure rate as natural deployment prevalence.

The task is authored and finite. The full correct publisher program contains the
reference implementation in positive controls; the negative program contains a
natural greedy shortcut. Reference predicates and supplied algorithm names can
make a fault recognizable, so actual agent calibration must establish difficulty.
The implementation is not an upstream bug, independently generated peer program,
or guarantee of a novel finding. Any social experiment is a later decision.

Before the subsequent output-requirement experiment, a further design review
identified a label cue: correct code accompanied true claims, flawed code false
claims. The calibration agents did acquire data and validated their answers, but
that pairing cannot establish whether data acquisition is necessary. A new
same_program mode holds the greedy program and total fixed across true/false
finite claims, changing only the database. Reference-only qualification selects
greedy-success and positive-cost greedy-failure worlds; cost doubling and a uniform
source-edge shift align reports without changing any optimization choices.
This prospective change is separate from the completed legacy calibration.
