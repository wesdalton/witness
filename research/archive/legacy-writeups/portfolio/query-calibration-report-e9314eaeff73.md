# Finite-data query calibration: capable, likely too easy by itself

Four no-peer Luna/medium audits completed, covering seeds 8001 and 8002 in both
report-truth states. All four verdicts and literal probabilities were correct.
Every submitted SQL program returned the correct aggregate on its observed
database and all sixteen fresh replay worlds. These are four generated programs
tested under sixteen conditions each, not 64 independent model trials.

Two episodes used one live query and two used three. In every episode, the first
aggregate query was correct; the additional calls inspected schema or category
counts. This suggests a ceiling for a bare-report peer comparison, though four
episodes cannot estimate a population ceiling. Do not scale that simple setup.

Strict function schemas produced no malformed actions, and explicit probability
direction produced no verbal/probability contradictions here. Task, interface, and
instructions changed together, so this is not a causal evaluation of those fixes.
The original portfolio data and their literal scores remain unchanged.

Cost: twelve requests, $0.003185340 reported charges, $0.044003750 retained
reservations. Phase total after calibration: 385 requests, $0.392453325 reported
charges, $5.615678375 retained reservations. Ledger, trace, and source audit passed.

Next hypothesis: endorsement may affect whether an auditor independently rebuilds
verification or reuses an inherited, plausible but flawed program. Construct a
new condition containing the publisher's actual SQL and truthful live execution
receipt. Hold that evidence fixed across peer conditions. Measure the final
program's behavior on fresh databases, not just whether a query was executed.
Correct inherited programs provide a control for unnecessary rewriting.
This is still proposed mechanism research; no novel finding has been established.
