# Development hypothesis: does asking for an executable verifier change the audit?

Draft during route capability calibration; no paid dispatch authorized by this
document. The original allocation task allowed voluntary investigation, whereas
the inventory and route tasks require a final executable verification artifact.
That requirement may be an intervention, not a neutral measurement device.

Competing explanations for repeated capability ceilings:

1. The tasks are intrinsically straightforward for this configuration.
2. Requiring a reusable verifier elicits independent checking that an ordinary
   verdict request would not elicit.
3. The full supplied program makes the flaw obvious, regardless of the output
   requirement; successful repair need not show independent construction.
4. Explicit auditor instructions, medium reasoning, or weak authored peer text
   dominate the contextual influence. Current comparisons do not isolate these.

A prospective test could randomize the requirement to submit reusable SQL versus
verdict-only submission, crossed with neutral versus endorsement messages, holding
the task contract, program, receipt, database, and tool budgets fixed. The primary
common endpoint must be claim judgment, not a program that one condition was not
asked to produce. Live-query acquisition and any program quality are secondary;
source-only verification is valid and cannot be assigned zero quality by absence.

Do not strip relevant task information or tune endorsement intensity to force a
failure. Rewrite the prospective shared task contract to exclude output-format
instructions in both arms, then vary only the system paragraph and submit schema.
Keep matched truth controls and fixed fresh seeds. Freeze all interfaces, analysis,
failure handling, and maximum reservation before any new calls. This would be an
artifact-requirement intervention; it would not identify a psychological mediator.

Mandatory checking and independent verification already have substantial prior
work, including Witness's own earlier reserved-verification design. A result must
be more specific than 'verification helps' and independently replicate before
any novelty claim. Review route calibration and literature first; a task that is
still easy is not automatically improved by making the auditor less capable.
