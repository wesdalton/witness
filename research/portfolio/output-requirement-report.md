# Completed matched output-requirement screen

All 32 live auditors completed and gave correct judgments. Every auditor queried
the database. All sixteen requested final SQL programs passed thirty fresh replay
conditions each. No accuracy difference between the tested output requirements
or peer messages appeared. This small ceiling result does not establish equivalence,
general robustness, intrinsic task difficulty, or a novel behavioral mechanism.

The frozen [protocol](output-requirement-protocol-v1.md) crossed program versus
verdict-only output with neutral versus endorsement messages on four seed blocks,
each containing true and false finite claims. The complete initial evidence was
identical across truth states: the same greedy SQL, claimed total and truthful
execution receipt. Only the hidden database differed. Across intervention arms,
the database and substantive evidence were held fixed. Saved-record equality
checks passed. Peer text was authored; these were live individual auditors, not
an independently executing swarm.

The primary exploratory Brier contrast, program minus verdict on endorsed false
claims, was **+0.00000025**, far below the predefined 0.05 interesting threshold.
Each of the four accuracy contrasts had four matched pairs and zero difference;
its conservative 95% interval was [-0.66563, +0.66563]. There are four seed blocks,
not 32 independent tasks. Neither this interval nor the flat point estimate rules
out meaningful effects. [Machine-readable analysis](output-requirement-analysis.json)
retains individual pairs and secondary contrasts.

Program-mode episodes used 55 queries and verdict-only episodes 50. Neutral
episodes used 54 and endorsement episodes 51. Eight calls failed because they
contained multiple SQL statements; all recovered within their budgets. These were
ordinary query errors, not Daybreak rejections. The 105 calls include inspection,
failed execution and substantive optimization, so call count is not verification
quality. All optimization programs and final justifications were reviewed.
Episode 014 in verdict mode used a complete path list and a valid manual
optimality argument; it need not return an unrequested aggregate program to verify
the claim. No final probability/verdict contradiction was found.

Only program-mode submissions have artifact scores. Their 30-condition replays
test unchanged SQL against qualified greedy traps, ordinary and renamed graphs,
and six boundaries; they are not additional model trials. Absence of a requested
artifact in verdict mode is recorded as null. No artifact-quality treatment
contrast is identified by these missing outputs.

After completion, free boundary review exposed an unbounded-integer defect in the
v1 contract. All observed and replayed graphs have small exact integer answers,
so their finite scores remain valid. Universal program correctness is unsupported.
The [separate adjudication](route-numeric-adjudication.json) preserves the numeric
counterexample and all raw records; [contract v2](route-protocol-v2.md) bounds costs
prospectively. This is a specification defect, not an agent error.

The batch used 124 API requests, $0.030558295 reported charges and $0.489633000
retained reservations. Phase totals after it: 559 requests, $0.437914035 charges,
$6.299725000 retained reservations against the unchanged $25 ceiling. Reservations
are conservative limits, not charges. There were no retries or replacements.

Decision: decline a larger replication of these ceiling conditions. Test one
smaller capability question next: with a single query, does the auditor allocate
its first evidence request usefully? This changes the resource/interface package,
so comparisons with historical eight-query runs remain descriptive. Freeze and
validate that pilot separately before spending.
